# Phase 1 portable fixture specification

This specification defines verification data only. It is not an accepted event encoding or a persistence/replay contract. Phase 2 formats remain an ADR-0005 design topic.

The fixture has exactly 25 bytes with no padding. Values are unsigned. Multi-byte fields use little-endian order, independent of host CPU, Odin struct layout, and alignment.

| Field | Byte offset | Width | Representation |
|---|---|---|---|
| schema | 0 | 1 | unsigned 8-bit value |
| task | 1 | 8 | unsigned 64-bit little-endian |
| run | 9 | 8 | unsigned 64-bit little-endian |
| tick | 17 | 8 | unsigned 64-bit little-endian |

The independent golden example uses schema 1, task `0x0102030405060708`, run 2, and tick 3. The task's least significant byte comes first: `08 07 06 05 04 03 02 01`. Run and tick have one nonzero low byte followed by seven zero bytes. Concatenating these fields produces the fixed sequence in `tests/fixtures/phase1.golden.hex` and the literal expected array in `tests/odin/foundation/foundation_test.odin`.

The expected bytes are never generated by Warband's encoder during the test. A separate Python standard-library `struct.pack('<BQQQ', ...)` reference may check the static golden sequence; it does not import or call the Odin implementation. The round-trip test is supplemental and does not replace this golden comparison.
