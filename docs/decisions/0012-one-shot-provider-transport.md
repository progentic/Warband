# ADR-0012: One fixed HTTPS request per send opportunity

## Status and scope

Proto accepted the six design rulings against package 3a on main at `30310240de23f124c5e1e5544896210c40cdd4bb`, tree `cc84c2fa08665a4a5d6d107f7af2eba464ce5760`. Package 3b uses synthetic credentials and an isolated TLS endpoint on preproduction x64-review. The [approved scope](../engineering/phase4-increment3-scope.md), [projection profile](0010-provider-adapter-boundary.md#package-3a-projection-and-envelope-profile) and [intake decision](0011-atomic-model-request-consumption.md) govern its interfaces. Review of the exact decision text precedes effectful implementation.

## Six rulings

1. **Accept the connected-socket interface.** The connector hands over one connected TCP descriptor and its independently selected peer address and port. Check socket type, family and actual peer before TLS. Bind the fixed hostname and port to that numeric address in libcurl's per-handle resolution cache to avoid a second DNS lookup. The open-socket callback can yield the verified descriptor once, transferring close ownership to libcurl. Refuse subsequent socket requests. The socket-option callback returns `CURL_SOCKOPT_ALREADY_CONNECTED` for that descriptor. Preserve the compiled hostname for SNI, certificate verification and HTTP authority. The synthetic launcher supplies the socket in 3b. The trusted resolver/connector and external destination policy supply it in 3c. [Open-socket callback](https://curl.se/libcurl/c/CURLOPT_OPENSOCKETFUNCTION.html) · [Socket-option callback](https://curl.se/libcurl/c/CURLOPT_SOCKOPTFUNCTION.html) · [Per-handle resolution](https://curl.se/libcurl/c/CURLOPT_RESOLVE.html)
2. **Accept one transport process per issuance.** The launcher spends the issuer's in-memory send opportunity atomically before spawning or requesting a connection. Exactly one caller wins a duplicate handoff. Spawn failure, cancellation, timeout, process death and lost reply all leave it spent. A restarted launcher cannot reconstitute it from an ID. Each transport accepts one tuple, owns one fresh easy handle, performs at most one transfer, releases its resources and exits. This spend has no effect on kind-11 consumption. The front end receives bounded response bytes for 3a extraction and has no Internet sockets or credential.
3. **Force HTTP/1.1.** Set `CURLOPT_HTTP_VERSION=CURL_HTTP_VERSION_1_1` and verify the observed protocol at the fixture endpoint. One request has no multiplexing requirement. One framing model gives the header and body counters an unambiguous unit.
4. **Select sealed memfd delivery.** A trusted bootstrap in the credential-handling domain provisions the memfd, verifies its type, bounded length and write/grow/shrink/seal seals, and passes it only to the intended transport. A readable descriptor itself confers access. Keep it out of the issuer and front end, close bootstrap duplicates, and inventory inherited descriptors. The transport verifies the seals, reads once, rejects empty, oversized or header-unsafe values and closes the fd during preflight. Disable dumps after the final credential transition, scrub secret-bearing buffers under application control, free the header list, and remove proxy and TLS-key-log environment settings. Only the trust bootstrap and credential-bearing identity may handle plaintext. File-path loading is a contingency requiring a separately reviewed configuration. Missing memfd fails closed.
5. **Use this ADR as the 3b decision record.** Its fixture launcher plays the issuer through the same bounded interface. Credential provisioning uses a synthetic token. Production issuer integration, project-sharing verification and live egress keep their separate gates.
6. **Require first-cause abort evidence.** Before aborting a transfer callback, latch its first typed cause. Report that cause ahead of libcurl's generic read, write or abort result. Distinguish header limit, body limit, request limit, framing, cancellation and deadline. For a completed HTTP response, classify 429 as rate-limited and other non-2xx as HTTP failure. Keep the numeric HTTP status when observed, bounded counts, request ID, profile ID and typed result. Discard raw response/error text and the private error buffer. A disappearing issuer may leave no child result; the surviving supervisor records the observed loss without guessing whether the peer received a request.

## Handoff and deadlines

Use a launcher-created inherited Unix sequenced-packet socket. Verify the expected creator identity from kernel peer credentials, and verify the child identity through the launcher's process and descriptor custody. On Linux a socketpair's peer credentials describe the creator at pair creation. They do not attest a new UID or PID after fork/exec. Reject malformed, truncated or oversized frames, unexpected descriptors and incorrect message order. [Unix socket credentials](https://man7.org/linux/man-pages/man7/unix.7.html)

Separate tuple acceptance from permission to connect. First deliver the fixed versioned tuple (issued ID, catalog revision/identity, absolute BOOTTIME deadline). The transport checks the tuple, credential, clock and complete 3a request length before signaling Ready. Only then may the launcher/connector spend the network attempt and deliver its single fd. Keep the control channel open for cancellation or EOF until the terminal disposition. Close unused channel ends in every process. Arm Linux parent-death signaling after UID changes and recheck the expected parent to cover death during setup. If issuer and launcher are distinct, monitor issuer liveness explicitly. [Parent-death semantics](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

Use the earlier of issuance expiry and 30 seconds from call start. Resolution, TCP connect and TLS together share the first five seconds and the remaining total budget. Pass absolute cutoffs across the connector handoff so TLS gets only the remaining setup time. Refuse zero remaining time before converting deadlines to libcurl millisecond options. Set connect and total timeouts, enable the progress callback, and check fresh BOOTTIME in callbacks and on return. Monitor cancellation and deadline independently during idle waits, waking or terminating the transfer and reaping the process at expiry. Never acknowledge success after the deadline. Bytes already received by the endpoint remain observable after cancellation. [Progress callback cadence](https://curl.se/libcurl/c/CURLOPT_XFERINFOFUNCTION.html)

## Fixed transfer and qualification

Check all required option results before transfer. Use the compiled HTTPS URL, HTTPS-only protocols, redirect following off, an empty proxy setting even with proxy environment variables present, fresh connection, forbidden reuse, no shared handle, retries or authentication negotiation. Require peer/hostname verification, TLS 1.2 or later, identified roots, and ordinary post-handshake HTTP transmission with TLS early data disabled. Use only the fixed JSON content type and bearer credential as application headers. Include an explicit empty `Expect:` entry in libcurl’s fixed header list to suppress its generated `Expect: 100-continue` header at every body size. Refuse an upload rewind. Exercise 401, 407 and 417 with independent HTTP request counts, since a single TCP connection can carry multiple requests. Suppress content-encoding negotiation and automatic content decoding. Accept absent or identity content encoding only. Validate response framing, including conflicting lengths and transfer framing.

Build the complete body before Ready. Use the 3a bytes as the sole upload source, declare their exact size, and enforce the 16 KiB upload budget in the read callback as well as during preflight. Count all header blocks, interim responses and trailers against one 16 KiB budget. Count decoded transfer-framing body bytes against 64 KiB while reading. Check remaining capacity before copying. Once a failure is latched, discard partial body data. Return complete successful bytes to the front end.

| Fixture or inspection | Acceptance criterion |
|---|---|
| Valid control and duplicate launcher delivery | One winning handoff, one process, one connection and one fixed HTTP/1.1 POST. The endpoint independently checks peer, authority, path, headers and exact 3a body, including the absence of an `Expect` header on the wire. Re-submit after exit and restart: zero additional requests. |
| Missing or malformed credential, malformed tuple, expired handoff, pre-send cancel | Zero connector attempts and zero HTTP requests. After TCP setup but before HTTP send, cancellation can instead leave one connection and zero requests. |
| Cancellation, timeout, lost response or issuer death after endpoint receipt | Exactly one request, zero follow-ups, a reaped transport and a typed disposition. A silent TLS/body stall exercises the independent timer. |
| TLS, peer mismatch, redirects and proxy | Reject a wrong peer, untrusted chain or wrong hostname before sending the bearer header. A reachable fixture proxy receives zero connections despite proxy environment settings. Both same-host and cross-host redirects receive zero follow-ups. |
| Caps and first cause | At each enforcing callback, accept the cap and reject cap + 1, including fragmented bodies and interim headers plus trailers. Exercise five- and 30-second cutoffs at equality. Preserve the first cause when cancellation and a later generic error coincide. Use synthetic callback input for the 16 KiB upload boundary. The approved catalog produces 786- and 790-byte requests. |
| Actual library, roots and sanitization | Record executable and loaded libcurl path/hash, package/build version and inputs, enabled features/bitmask, named TLS backend and version, effective CA files/directories, provenance and digests. Collect linked-object inspection and in-process `curl_version_info` from the qualified binary. Independently check counters and sanitized evidence for leaks of the synthetic token and provider error canaries. |

Use distinct fixed fixture and production trust configurations. Demonstrate fixture acceptance for its issued certificate and rejection for a wrong hostname. Demonstrate that the production configuration rejects that fixture CA. Separately verify a suitable, lawfully available public chain with the actual production roots and its rejection under the fixture-only roots, checking hostname and validation time. Record offline chain verification and endpoint handshakes as distinct evidence. A public certificate chain alone cannot prove a successful TLS handshake for the fixed production hostname. Any outstanding positive live handshake stays at the live-egress gate. Record effective trust directories as well as the CA bundle so an ambient trust source cannot make the negative control pass unexpectedly.
